# SENTRIX — Seller Delivery-Risk Intelligence Platform

Predicts which marketplace sellers (suppliers) are likely to have a late
delivery in the next 30 days, explains **why** each prediction was made, and
lets a non-technical user interrogate the results in plain English.

## Data provenance — read this first

| Layer | Source | Status |
|---|---|---|
| Sellers, orders, order items, products | Olist Brazilian E-Commerce (Kaggle, CC BY-NC-SA) | **REAL** |
| Customer reviews (sentiment features) | Olist | **REAL** |
| Late-delivery label | Computed: `order_delivered_customer_date > order_estimated_delivery_date` | **REAL** |
| Commodity (fuel) volatility | FRED — Federal Reserve Economic Data, real daily WTI oil prices | **REAL** |
| Weather / port congestion signals | Generated per real seller-state + real date | **SYNTHETIC** |

**Real scale:** 3,095 sellers · 99,441 orders · 112,650 order items · 99,224 reviews · **8.11% genuine late rate**.

### Why part of the signal layer is synthetic — and why *that specific part*

The orders span **Sept 2016 – Oct 2018**, so any external-signal API has to
return data *for those dates*. Each free tier was evaluated against that
requirement:

| Signal | Free-tier reality | Decision |
|---|---|---|
| **Commodity** | FRED serves decades of free daily history, queryable by date range | **Use real data** |
| Weather | OpenWeatherMap free tier is current/forecast; multi-year history is paid | Generate |
| Port congestion | No free public source for historical port congestion | Generate |

Using a live news or weather API here would have silently mismatched 2026
data against 2017 orders — worse than generating it honestly. So the one
signal that free tooling *can* legitimately support was made real, and the
rest are generated **independently of the label**, so they cannot manufacture
a fake correlation.

**Provenance is enforced in the database, not just claimed here:** every
`external_signals` row stores `is_synthetic` (0 = real FRED, 1 = generated),
and a test (`test_signal_provenance_is_explicit`) fails the build if any row
is ambiguous or if weather/port is ever mislabelled as real.

## Results (real chronological holdout, no shuffling)

| Model | PR-AUC | ROC-AUC | F1 | KS |
|---|---|---|---|---|
| **Logistic Regression** | **0.400** | 0.691 | 0.351 | 0.297 |
| Random Forest | 0.386 | 0.717 | 0.403 | 0.327 |
| LSTM (PyTorch) | 0.385 | 0.714 | 0.343 | **0.360** |
| LightGBM | 0.374 | 0.693 | 0.385 | 0.279 |
| XGBoost | 0.354 | 0.692 | 0.360 | 0.271 |
| Stacking Ensemble | 0.280 | 0.656 | 0.250 | 0.247 |

Base rate ≈ 17% → the best model gives **~2.4× lift over random**.

Two findings worth stating plainly rather than hiding:
- **The simplest model won.** With well-engineered features, Logistic
  Regression beat the boosted trees. This is exactly why baselines exist.
- **The ensemble underperformed.** Its internal base models were lightened
  for compute budget, and stacking can overfit under a temporal split.

## Feature families (30 features, seller-day grain)

1. **Delivery history** (REAL) — rolling 7/14/30-day late counts & rates, trend, recency
2. **Review sentiment** (REAL) — rolling mean review score, bad-review counts
3. **External signals** (MIXED) — commodity volatility from real FRED oil
   prices; weather / port generated by seller state
4. **Profile & peer** (REAL) — lifetime late rate, state-peer rate, tenure

**Leakage control:** every feature looks strictly backward via `.shift(1)`;
the label looks strictly forward. Train/test is split chronologically, never
shuffled.

## Run it

```bash
python -m venv venv && venv\Scripts\activate      # Windows
pip install -r requirements.txt
copy .env.example .env                            # fill in MySQL creds

python -m src.ingestion.schema                    # create tables
python -m src.ingestion.olist_loader              # load REAL Olist data
python -m src.ingestion.synthetic_signals         # signal layer (real FRED + generated)
python scripts/build_features.py                  # 380K-row feature table

python -m src.models.trainer --stages baseline boosting ensemble lstm
python -m src.evaluation.run_evaluation
python -m src.evaluation.generate_predictions
python -m src.models.mlflow_tracking
python -m src.rag.indexer

pytest tests/ -v                                  # 34 tests

uvicorn api.app:app --reload --port 8000          # terminal 1
streamlit run frontend/dashboard.py               # terminal 2
```

## Notes

- Training hyperparameters (Optuna trials, LSTM epochs) are tuned down in
  `config.yaml` for a constrained environment; raise them locally.
- The RAG embedder falls back to TF-IDF when `huggingface.co` is unreachable;
  retrieval mechanics are identical and it switches back automatically.
- `FRED_API_KEY` (free: https://fred.stlouisfed.org/docs/api/api_key.html)
  enables the real commodity signal. Without it the pipeline still runs —
  commodity falls back to generated values, flagged `is_synthetic = 1`.
- Airflow requires its **own isolated environment** (it pins `sqlalchemy<2.0`,
  which conflicts with this stack) — see `requirements-airflow.txt`.
